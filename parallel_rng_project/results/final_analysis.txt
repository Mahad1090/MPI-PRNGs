── Roofline Analysis ─────────────────────────────────────────────

  Peak memory bandwidth (STREAM copy) : 10.04 GB/s
  Peak compute (FMA)                  : 5.76 GFLOPS
  Ridge point                         : 0.574 FLOP/byte

  Single Core Threefry-4x64-20 (Authors Baseline):
    Arithmetic Intensity  = 2.50 FLOP/byte
    Status: COMPUTE-BOUND (AI > ridge point)
    → Threefry is limited by CPU throughput, not memory bandwidth.
    → Adding more MPI processes increases throughput proportionally.
    → This is why near-linear MPI speedup is expected.

  MPI Threefry (Our CPU Contribution):
    Arithmetic Intensity  = 2.50 FLOP/byte (same as single core)
    MPI adds negligible overhead (one MPI_Reduce of P doubles).
    → Each rank independently runs Threefry with zero inter-rank comms.
    → Embarrassingly parallel — near-linear speedup with process count.

  GPU Philox-4x32-10 (Our GPU Contribution):
    Arithmetic Intensity  = 1.00 FLOP/byte
    Status: MEMORY-BOUND on CPU roof, but GPU has far higher BW.
    → Philox 32-bit multiply is a native single-cycle GPU operation.
    → Thousands of CUDA threads saturate GPU memory bandwidth.

  Interpretation:
  • Efficiency > 90%: excellent scaling, MPI overhead is minimal.
  • Efficiency < 70%: excessive synchronization or load imbalance.
  • Threefry has zero communication during generation — any overhead
    comes only from MPI_Init, MPI_Barrier, and MPI_Reduce.
  • Super-linear speedup is possible if per-rank data fits in cache
    while the full N does not (cache-size effect).

── Key Conclusions ──────────────────────────────────────────────

  1. Counter-based PRNGs (Threefry, Philox) are embarrassingly
     parallel — each rank/thread independently computes its
     output from (key, counter) with zero communication.

  2. Single Core Threefry is the correct baseline — it is the
     authors' own implementation. MPI and GPU speedups measure
     pure parallelization benefit, not algorithm differences.

  3. Philox is optimal for GPU because it uses 32-bit multiply,
     which maps perfectly to GPU hardware units with zero
     warp divergence (all threads execute identical instructions).

  4. MPI Threefry achieves near-linear speedup because the
     parallel fraction is essentially 100% — communication
     cost is only two collective calls (Barrier + Reduce).
